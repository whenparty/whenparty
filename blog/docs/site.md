# Working on the site

- `eleventy.config.js` builds `src/` into `_site/`. To the Markdown of a post it adds an `id` on each heading, a `div.table-wrap` around each table, a class in place of each `style` that sets the alignment of a table cell, the cards and formula blocks that [posts.md](posts.md) describes, with the MathML of each formula in a `div.formula`. KaTeX renders it when the site is built, so the pages get no script, stylesheet or font of KaTeX, as [formulas.md](decisions/formulas.md) decides. After the build it copies the images of each built post into the post's folder in `_site/`, so the images of a draft stay out too. A post with `draft: true` is built only when Eleventy runs in serve or watch mode.
- To meet [serving.md](/docs/conventions/serving.md), the build adds `?v=` and the first 8 hex digits of the file's SHA-256 to the URL of `styles.css` and of each image of a post. `nginx.conf` sends `Cache-Control: public, max-age=31536000, immutable` for a style or image requested with `v` and for an audio file, whose name carries its hash, and `no-cache` for every other 2xx and 3xx answer, the pages included. Its 404s carry none.
- Under `/audio/` nginx serves only a file named as [posts.md](posts.md) says, `<post>.<8 hex digits>.mp3`, requested without a query. Anything else there answers 404: the folder itself, a file with another name, and a request with a query, which [Cloudflare](/infra/docs/setup.md#cloudflare) would cache apart from the file.
- The nginx proxy sets the Content-Security-Policy in [blog.conf](/infra/nginx/conf.d/blog.conf), which ships with the [nginx deploy](/.github/docs/deploys.md#infrayml), not with this folder, and which the `blog.when.party` row of `2-2` in [2-headers.md](/infra/docs/specs/2-headers.md) states. It blocks inline styles and inline scripts. The build is stricter: it fails when the text ` style=` or `<script` appears anywhere in the built HTML of a page. Markdown escapes `<` in code, so a code sample with `<script` passes and one with ` style=` fails. The pages load nothing from other hosts and use the fonts of the device; the policy, the same as that of `www.when.party`, would also allow Google Fonts and Cloudflare's analytics script. A new outside resource needs a change to that row and to `blog.conf`.
- `src/styles.css` repeats the fonts, the hand-drawn corners and the colours of the [games' page](/games/index/docs/page.md), [styles.css](/games/index/src/styles.css), with sage in place of denim. When one of them changes its look, ask the user whether the other follows.
- Through the proxy, every 404 of the site shows the shared 404 page, as `3-2` of [3-sites.md](/infra/docs/specs/3-sites.md) says, and `/_errors/` belongs to the proxy, as [nginx-configs.md](/infra/docs/nginx-configs.md#shared-settings-and-a-sites-own) says. A 404 page of the blog's own needs a change to `3-2` and to `blog.conf`.
- The proxy limits the requests that each client address starts at once and keeps in progress, as `2-4` of [2-headers.md](/infra/docs/specs/2-headers.md) says, so the images in the list of posts load lazily: a list that loads every picture at once would lose some of them as it grows.
- `docker-compose.yml` mounts the folder `audio/` next to it on the VPS, `/opt/services/whenparty/blog/audio/`, read-only as `/audio/` of the site. The container runs with a read-only file system, `tmpfs` for the folders nginx writes to, only the Linux capabilities `CHOWN`, `SETUID`, `SETGID` and `NET_BIND_SERVICE`, and `no-new-privileges`. The [deploy](/.github/docs/deploys.md#siteyml) copies only `docker-compose.yml`, so it never touches the audio files. [audio.md](audio.md) says who uploads them and how.
- The `Dockerfile` pins its Node and nginx images, and no other file changes with them. [image-scan.md](/.github/docs/image-scan.md) says how a scan tells that they need newer versions.
- To run the image as the deploy builds it, without drafts:

  ```bash
  cd blog
  docker build -t blog:local .
  docker run --rm -p 3002:80 blog:local
  ```

  Then open http://localhost:3002. The container sends none of the proxy's headers, so a local run does not show what the Content-Security-Policy blocks.
- A push to `main` that changes a file in `blog/` other than Markdown, or a post, runs [blog.yml](/.github/workflows/blog.yml), which deploys through [site.yml](/.github/workflows/site.yml), as [deploys.md](/.github/docs/deploys.md) says.
