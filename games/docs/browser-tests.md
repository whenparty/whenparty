# Browser tests

`pnpm test:browser` from `games/` runs every [`*.browser.test.ts`](/docs/conventions/tests.md) of `games/` with [playwright.config.ts](../playwright.config.ts). Its arguments go to `playwright test`, such as the folders of the packages to test, `pnpm test:browser platform/transport`, or a requirement, `pnpm test:browser -g '8-5 '`. It needs Docker. [browser-tests.md](decisions/browser-tests.md) explains why the tests use these browsers and servers.

## Servers

- [tests/browser.sh](../tests/browser.sh) starts coturn in Docker with the [turnserver.conf](../platform/turn/turnserver.conf) and [start.sh](../platform/turn/start.sh) of the [turn deployment](../platform/turn/AGENTS.md), as [`smoke.sh`](../platform/turn/docs/smoke-test.md) does, at `11.11.11.10` on an internal Docker network whose addresses no denied range of coturn covers. It adds `max-allocate-lifetime` to the config, so that Chrome refreshes its allocations within seconds: Chrome refreshes an allocation after half its lifetime when the lifetime is under 2 minutes. The test of `8-6` in [8-turn.md](../platform/transport/docs/specs/8-turn.md) needs a refresh after the credentials expired. `browser.sh` also adds `verbose`, so that coturn's log shows each allocation and each peer address that coturn refuses, with its time. It keeps the denied ranges of the config, as [browser-tests.md](decisions/browser-tests.md#decision) explains.
- [tests/servers.mjs](../tests/servers.mjs), the global setup of Playwright, starts in Node:
  - [signaling](../platform/signaling/AGENTS.md) with the [rooms server](../platform/rooms/docs/specs/1-room.md) at `localhost:8080`, where pages on `localhost` connect to the transport server (`1-13` of [1-signaling.md](../platform/transport/docs/specs/1-signaling.md)), without a TURN secret, so that no page asks coturn at `turn.when.party` (`8-1` of [8-turn.md](../platform/transport/docs/specs/8-turn.md));
  - signaling with coturn's test secret at `localhost:8081`;
  - Vite with the test pages of the [modules](/docs/glossary.md#module), from `games/`, at `localhost:5173`, and each title with its own config: tictactoe at `localhost:5174/tictactoe/` and calisthenics at `localhost:5175/calisthenics/`. None watches files, so an edit during a run reloads no page under test.

## Browsers

- [playwright.config.ts](../playwright.config.ts) runs every test in Chromium, Chrome in CI, and, apart from the tests tagged `@chromium`, in WebKit, the engine of Safari. A test takes the tag when WebKit cannot run it for a cause in the test, such as the read of the clipboard that WebKit refuses to a test, or when it fails in WebKit for a cause not found yet, until a run finds it; a test that fails in WebKit for a cause in the page or the module is a failure to fix. The other tags come from a run in WebKit in the Playwright image on 2026-11-22, and no run has tried those tests in WebKit on the CI runner: two pages of a title did not connect, the guest staying at "Looking for room", also with camera and microphone permission, while the two pages of the tests of transport did, so every test of two players of a title takes the tag; in the test of `3-9` in [3-connection.md](../platform/transport/docs/specs/3-connection.md), the helper that uses up coturn's allocations got no refusal; and in the test of `8-5` in [8-turn.md](../platform/transport/docs/specs/8-turn.md) in which only one side has credentials, the page without them stayed connecting. `pnpm test:browser --project chromium` or `--project webkit` runs one browser.
- Locally, `browser.sh` runs Playwright in the Playwright image of the `@playwright/test` version in `package.json`, in its Chromium and WebKit. The container installs the workspace with the host's `node_modules` hidden, so the host keeps its own, and keeps pnpm's store in the Docker volume `games-browser-tests-pnpm`. It uses Docker's host network, which reaches coturn's network as the CI runner does; that holds on Linux and with Docker on a Mac, where the Mac itself does not reach it. The servers take the ports 8080, 8081 and 5173 to 5175 of that network, so a signaling or Vite server started for local play makes the run fail.
- In CI, where `CI` is set, `browser.sh` runs Playwright on the runner, in its Google Chrome and in Playwright's WebKit, and the workflow installs the workspace and WebKit, with the libraries it needs, before it.
- Chrome starts with `WebRtcHideLocalIpsWithMdns` off, so candidates carry addresses instead of mDNS names.
- Playwright adds `--enable-unsafe-swiftshader` to Chromium and Chrome by default, not through `playwright.config.ts`, so without a GPU they draw WebGL with SwiftShader, a software renderer. The tests of the 3D page of calisthenics need it.

## Test pages

- The test page of transport, in `platform/transport/src/tests/`, connects to `localhost:8081` and gives its peer connections coturn's address in place of `turn.when.party`. A test can make it relay-only, give it no TURN servers, or give it other credentials. It can also hold allocations under one username, on peer connections of the browser that connect to nothing, until the `user-quota` of [turnserver.conf](../platform/turn/turnserver.conf) makes coturn refuse one. The test of `3-9` in [3-connection.md](../platform/transport/docs/specs/3-connection.md) does this before its call, so that coturn has no free allocation for the caller. Its tests give the pages camera and microphone permission: without it, Chrome offers candidates only on the interface of the default route, whose address coturn denies, and with it, also on the bridge to coturn's network.
- The test page of rooms, in `platform/rooms/src/tests/`, uses the browser environment of rooms, so it connects to `localhost:8080`.
- The tests of tictactoe and calisthenics open their pages. Like them, give each player of a test a browser context of its own, because the pages of one context share the tab lock of rooms (`9-1` and `9-2` of [9-tab.md](../platform/rooms/docs/specs/9-tab.md)).
- Like the fixtures of rooms, tictactoe and calisthenics, make a test that opens rooms of the rooms module leave them when it ends, also when it fails, and wait until its pages have closed their signaling connections: the rooms server of a run keeps at most 10 open rooms (`12-1` of [12-server-answers.md](../platform/rooms/docs/specs/12-server-answers.md)), and a room that its owner's page did not leave stays open for minutes (`10-3` of [10-server-room.md](../platform/rooms/docs/specs/10-server-room.md)).
- The tests of calisthenics open its 3D page and its text page, as its [verification.md](../titles/calisthenics/docs/verification.md) says.

A failed run leaves its results in `test-results/`, with coturn's log in `coturn.log`, and in CI also the HTML report in `playwright-report/`; CI uploads both folders, as [checks.md](/.github/docs/checks.md) says. When the peer connection of a test of transport does not open on both pages, its failure also prints what the transport told each page, such as the reason with which a page closed.

## End-to-end tests on the images

[tests/e2e.sh](../tests/e2e.sh) runs the browser tests of the titles on built images behind the proxy, as players reach them, and `games.yml` runs it before each deploy, as [deploys.md](/.github/docs/deploys.md#gamesyml) says. Its arguments name the image of each deployment with a `Dockerfile`, such as `games/titles/tictactoe=whenparty-games/tictactoe`, and it fails when one has none. It needs Docker, Google Chrome and the port 443 of `127.0.0.1`.

- It creates the Docker network `wp_games` and starts each deployment of `games/` with a `Dockerfile` from its own `compose.yml`, and coturn from the `compose.yml` of the [turn deployment](../platform/turn/AGENTS.md), with a test TURN secret that signaling gets too.
- It starts nginx, in the image of [infra/docker-compose.yml](/infra/docker-compose.yml), on that network and on `127.0.0.1:443`, with a copy of [infra/nginx/conf.d/](/infra/nginx/conf.d/) and certificates that it creates for `when.party` and `nii.au`. The copy turns `ssl_verify_client` off, because the browser has no client certificate of Cloudflare (`1-2` of [1-connections.md](/infra/docs/specs/1-connections.md)); the rest of the proxy, its headers and limits included, is that of production.
- With `GAMES_E2E` set, [playwright.config.ts](../playwright.config.ts) runs only the tests in `titles/` and only in Chrome, starts no servers, runs one test at a time and starts Chrome with `games.when.party`, `signaling.when.party` and `turn.when.party` mapped to `127.0.0.1` and with certificate errors ignored. The tests open `https://games.when.party/<title>/` and connect to `wss://signaling.when.party/platform` (`1-13` of [1-signaling.md](../platform/transport/docs/specs/1-signaling.md)). One test runs at a time because every page reaches nginx from one address, and the per-address limits of `default.conf` are those of one player.
- coturn's config denies relays to private addresses, so the pages connect directly; the tests of transport check the relay on their own test page.
- When the tests fail, it prints how many answers of each status nginx gave, and it removes the containers and the network when it ends.
