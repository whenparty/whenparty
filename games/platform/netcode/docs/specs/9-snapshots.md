# Snapshots

- `9-1` Action numbers and snapshot numbers are integers from 1 to 2⁵³ − 1, match numbers are integers from 0 to 2⁵³ − 1, and room times are as [6-1](6-time.md) says. Terms and public numbers are as the rooms module gives them ([1-5](../../../rooms/docs/specs/1-room.md)). A page drops a text from another page in which such a number has another form before it compares anything but the versions of a snapshot ([3-5](3-entry.md)).
- `9-2` A snapshot holds: the state, which for a title without "lobby" is null before the first match ([5-9](5-matches.md) says where it starts for a title that gives "lobby"); whether a match runs; the match ID ([5-5](5-matches.md)); the public number on each seat, or none; the spectators' queue; the number of the last accepted action of each participant that has one ([8-5](8-actions.md)); the room time; the term of the host's page ([4-3](../../../rooms/docs/specs/4-owner.md)); and the snapshot number. It also carries the host's versions ([3-4](3-entry.md)). A snapshot fits in one text of the rooms module ([7-1](../../../rooms/docs/specs/7-texts.md)).
- `9-3` The first change of a term ([4-3](../../../rooms/docs/specs/4-owner.md)) makes snapshot number 1, and each further change of the term adds 1. A snapshot is newer than another when its term is higher, or when its term is the same and its number is higher.
- `9-4` Only the host makes changes, one at a time, in the order their causes arrive. The changes are an accepted action ([8-5](8-actions.md)), the start of a match ([5-2](5-matches.md)), an arrival ([4-4](4-seats.md)), a leave ([4-6](4-seats.md)), a call of "presence" for an event about a player ([5-6](5-matches.md)), a deadline ([7-1](7-deadlines.md)) and the end of recovery ([10-3](10-recovery.md)). A refused action, an event about a participant that calls no "presence" and is no leave, and a failure of a function that leaves the state as it was are no changes: the snapshot stays the same, and the host keeps of them only the context ([4-8](4-seats.md)) and the skipped times ([7-4](7-deadlines.md)).
- `9-5` The host writes each snapshot to the record ([9-7](../../../rooms/docs/specs/9-tab.md)) before any page can take it, and sends it also when writing failed.
- `9-6` The netcode keeps its data in the record data of the rooms module ([9-7](../../../rooms/docs/specs/9-tab.md)), under no storage key of its own: its versions ([3-4](3-entry.md)), and on the host's page the last snapshot and the room time, and on a participant's page the number of its last action ([8-3](8-actions.md)). It writes them only through the rooms module, which writes the whole record each time.
- `9-7` After each change, the host sends the snapshot to each participant whose connection to the host's page is open ([7-2](../../../rooms/docs/specs/7-texts.md)). When a participant's connection opens, with "joined" or "back", and the opening causes no change, the host sends that participant its last snapshot.
- `9-8` The host's page takes each snapshot that it makes.
- `9-9` A participant's page handles each snapshot from the host in this order. It reads the versions ([3-5](3-entry.md)). It drops the snapshot when a number in it has another form (9-1), its state is neither null nor passes "is state", or the rest does not have the form of 9-2. It takes the snapshot when it is newer than the last one the page took. A snapshot with the term and number of the last one the page took it neither takes nor drops, since it can complete a return ([3-6](3-entry.md)). It drops any other snapshot.
