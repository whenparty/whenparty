# Actions

- `8-1` A page can act while all of these hold: the game goes on for it ([2-1](2-page.md)); it has taken a snapshot, and in the last one its participant sits on a seat, and a match runs or the title gives "lobby" ([5-9](5-matches.md)); the netcode has not told it "host away" since it last told "host back" ([3-6](3-entry.md)); no action of its participant awaits an answer (8-4); and its next action number (8-3) is at most 2⁵³ − 1. While the game goes on, the netcode tells the page each time this changes.
- `8-2` When a page gives the netcode an action while it cannot act, or a value that fails "is action" or is larger than [1-3](1-rules.md) allows, the netcode sends nothing and answers the call with the first of these reasons that applies: "cannot act", "not an action" or "too large".
- `8-3` Otherwise the action gets a number: 1 more than the larger of the number in the page's record ([9-6](9-snapshots.md)) and the number of its participant's last accepted action in its last snapshot, or 1 when neither exists. On a participant's page, the netcode writes the number to the record, and then sends the host the action with its number and the match ID of its last snapshot, also when writing failed. The host's page neither sends its own action nor writes its number: the host judges it as 8-5 and 8-6 say, after the batch of [7-1](7-deadlines.md).
- `8-4` An action awaits an answer until the page takes a snapshot in which its participant's last accepted action number is the action's number or higher, or gets a refusal with the action's number. The page drops a refusal with another number.
- `8-5` When the host gets an action with a number higher than the last accepted number of its participant, or than 0 when it has none, the host judges it: it accepts the action when the participant sits on a seat, both parts of the match ID are those of the host's last snapshot ([5-5](5-matches.md)), a match runs or the title gives "lobby" ([5-9](5-matches.md)), the action passes "is action", and "step" with the participant's seat returns a state without failing ([1-4](1-rules.md)). Then the state becomes what "step" returned, and the number becomes the participant's last accepted. Otherwise the host refuses the action: the netcode tells only that participant's page that its action with this number was refused, and nothing changes on the host, which keeps no trace of the refusal.
- `8-6` When the host gets an action with a number that is not higher than the last accepted number of its participant, the host does not judge it and sends that participant its last snapshot.
- `8-7` When an action awaits an answer and a return completes ([3-6](3-entry.md)) with a snapshot whose last accepted action number for the participant is lower than the action's, or that has none, the page sends the action again with the same number and the same match ID as when it first sent it, and the host judges it as 8-5 and 8-6 say.
- `8-8` The host drops every text from a participant that is not an action of the form that the netcode sends, and a participant's page drops every text from the host that is neither a snapshot nor a refusal of that form.
