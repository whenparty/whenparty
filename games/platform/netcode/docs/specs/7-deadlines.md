# Deadlines

- `7-1` While a match runs, before the host judges an action ([8-5](8-actions.md)) and before it makes any other change except the end of recovery ([10-3](10-recovery.md)), it makes a batch: it reads room time once and then, while the earliest time that "deadlines" returns for the current state and that the host does not skip (7-4) is not later than the time read, it makes a change that calls "deadline" with that time.
- `7-2` After each change while a match runs, the host sets a timer for the earliest time that "deadlines" returns for the new state. Times that come during a batch wait for the timer. When the timer fires, the host makes a batch, as a cause in the order the causes arrive.
- `7-3` The host gives at most 100 times to "deadline" in one batch. "deadlines" fails when it returns a time later than 2³¹ − 1 milliseconds after the room time that the host read last, or, after the host gave 100 times to "deadline" in a batch, a time not later than the time read. "deadline" fails when it returns a state for which "deadlines" returns a time not later than the one that "deadline" got.
- `7-4` When "deadline" or "deadlines" fails, the batch ends, and until its next change the host skips times: it gives them to no call of "deadline", also in a batch that it makes before that change, and sets its timer for the earliest time that it does not skip. After "deadline" failed, it skips the time that "deadline" got and every earlier time. After "deadlines" failed in a batch in which the host gave 100 times to "deadline", it skips every time not later than the time read. After "deadlines" failed otherwise, it skips every time.
