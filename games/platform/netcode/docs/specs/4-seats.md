# Seats

- `4-1` When the rooms module asks the host's page whether to let a participant in ([6-1](../../../rooms/docs/specs/6-presence.md)), the host first compares the versions in the join data of the request with its own ([3-4](3-entry.md)). When they differ, the host refuses with its versions as the join data of the refusal ([3-5](3-entry.md) says what the entering page does). When the join data does not have the form of [3-4](3-entry.md), the host refuses without join data, and the entry fails with "refused" ([2-13](2-page.md)). The host compares no versions after it answers the request.
- `4-2` When the host does not refuse as 4-1 says and no match has started, which is when the match number of the host's last snapshot is 0, the host lets the participant in when the title gives no "admit" or "admit" answers yes, and refuses otherwise.
- `4-3` When the host does not refuse as 4-1 says and a match has started, the netcode tells the host's page of the join request with the participant's public number ([1-5](../../../rooms/docs/specs/1-room.md)), and lets the participant in or refuses as the page answers. When the rooms module ends a request that the page has not answered ([6-2](../../../rooms/docs/specs/6-presence.md)), the netcode tells the page so. An answer to a request that was answered or has ended changes nothing. The netcode has no time limit of its own for the answer.
- `4-4` When the rooms module tells the host's page that the connection of a participant opened for the first time ("joined", [6-5](../../../rooms/docs/specs/6-presence.md)), the participant arrives: while no match runs and a seat is free, it sits on the first free seat in the order of the seats; otherwise it joins the end of the spectators' queue. A participant that sits on a seat or is in the queue does not arrive again, and "back" is no arrival. The host arrives when starting completes ([2-3](2-page.md)).
- `4-5` While no match runs, each free seat goes to the first spectator in the queue, in the order of the seats, in the change in which the seat became free or the match ended.
- `4-6` When the rooms module tells the host's page that a participant left ("left", [6-5](../../../rooms/docs/specs/6-presence.md)), the participant leaves its seat or its place in the queue, and the host forgets the number of its last accepted action ([8-5](8-actions.md)). A seat that becomes free while a match runs stays free until the match ends.
- `4-7` The host is the room's owner, whose public number is 1 ([1-5](../../../rooms/docs/specs/1-room.md)). It sits on the seat it took when starting completed until it leaves the game: neither recovery nor the roster removes it, and it is never lost.
- `4-8` For each participant, the host's page keeps whether it is lost and whether its page is hidden, as the rooms module tells with "joined", "lost", "back", "hidden" and "visible" ([6-5](../../../rooms/docs/specs/6-presence.md)). For the host, it keeps whether the host's page is hidden.
