# Seats and matches

- `5-1` When the rooms module asks the host's page whether to let a participant in ([2-2](../../rooms/docs/specs/2-join.md)), the netcode lets it in when the title gives no "admit" or "admit" returns true, and refuses it otherwise. When the host's app is then told that the participant joined ([2-4](../../rooms/docs/specs/2-join.md)), the participant arrives: while no match runs, it takes the first free seat in the order of the seats, and otherwise it joins the end of the spectators' queue. The host arrives when it starts the game.
- `5-2` A match runs from its start until "over" returns true for its state. While no match runs, each free seat goes to the first spectator in the queue, in the order of the seats, until no seat is free or no spectator waits.
- `5-3` A player that is lost ([4-1](../../rooms/docs/specs/4-presence.md)) keeps its seat. When a participant leaves the room, it leaves its seat or the queue. A seat that is freed while a match runs stays free until the host's page seats a spectator on it, or the match ends. When the host's page seats a participant that is not a spectator, or on a seat that is not free, nothing changes and the netcode tells the page.
- `5-4` When the host's page starts a match, the match ID becomes a new random string of 22 characters, the match number grows by 1 from 0, and the state becomes what "initial state" returns. When the title's "can start" returns false, or, without "can start", when a seat is free, the match does not start, and the netcode tells the page. A match may start while another runs.
- `5-5` When the host's app is told a presence event about a player while a match runs ([4-1](../../rooms/docs/specs/4-presence.md)), the netcode calls "presence" with the player's seat, and the state becomes what it returns. A title without "presence" keeps the state. For "left", this is one change with the leave of 5-3.
- `5-6` After each change, the host sets a timer to the earliest room time that "deadlines" returns for the state, and calls "deadline" with that time when the room time reaches it, as a change. A deadline that the host already gave to "deadline" in the match is not given again.
- `5-7` Room time is the time since the host started the game, in milliseconds. The host counts it on its page's monotonic clock and stops it while it recovers ([6-2](6-recovery.md)). The netcode tells each page the room time as that of its last snapshot plus the time since the page took it, and stops counting while the page's participant is told "host away" ([2-9](2-game.md)).
- `5-8` When "initial state", "presence", "deadlines" or "deadline" throws, or returns a state that fails "is state" or makes the snapshot larger than [3-3](3-snapshots.md) allows, the state stays as it was, the netcode tells the host's page that the game has an error, and the host gives that deadline to "deadline" no more. A seat change of the same change still happens. When "admit" or "can start" throws or returns no boolean, it counts as false.
