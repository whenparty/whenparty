# TURN

`turn/` is the [deployment](/docs/glossary.md#deployment) of coturn at `turn.when.party`, which relays WebRTC traffic when direct connections fail. It is part of the [transport module](../transport/AGENTS.md), whose specification says which credentials it accepts ([8-2](../transport/docs/specs/8-turn.md)), and it also relays for the [p2p module](../p2p/AGENTS.md). [compose.yml](compose.yml) defines the container; [turnserver.conf](turnserver.conf) defines network restrictions and quotas. [start.sh](start.sh) adds the shared secret and detects the public address behind NAT.

## Deployment constraints

- Set the repository secret `TURN_SECRET` for both TURN and [signaling](../signaling/AGENTS.md). The [deploy workflow](/.github/workflows/deploy-project.yml) writes it to the private `.env` of both [deployments](/docs/glossary.md#deployment). TURN exits without it; signaling then issues no credentials.
- DNS for `turn.when.party` must point directly to the VPS without Cloudflare proxying. Open `3478/udp`, `3478/tcp` and `49152-49407/udp` in both firewalls. coturn has no TLS endpoint. Its container uses the host network: coturn relays each allocation on a port of its own from `49152-49407/udp` and needs the clients' real addresses, and publishing a range of ports through Docker is slow and hides those addresses.
- Keep the secret out of Git, logs and process arguments. The generated config belongs in private `/tmp` storage. Retain the container restrictions in Compose and its one added capability, `NET_BIND_SERVICE`: the image's `turnserver` binary carries it as a file capability, and the kernel refuses to run the binary when the container's bounding set lacks it. The capability allows nothing but binding ports below 1024, and coturn binds none.
- Deny private and special-use peer addresses. Keep the server's own public address allowed so two relayed clients can connect. No other UDP service may listen on that public address; inspect listeners with `sudo ss -ulpn` when provisioning.
- Do not add denied IPv6 ranges starting at `::`; coturn also matches IPv4 peers against them. Keep UDP relay allocations only and retain the resource quotas: 64,000 bytes a second for each allocation out of 8,000,000, so at most 125 allocations at once, and at most 32 for one username; [turn-credentials-limit.md](../docs/decisions/turn-credentials-limit.md) explains why they, and no limit on credentials, bound its use. When none is free, a peer connection that needs TURN closes with `no relay` ([3-9](../transport/docs/specs/3-connection.md)).

## Verification

Run `sh games/platform/turn/tests/smoke.sh` from the repository root when changing TURN configuration, startup or image. It needs Docker and checks the deployed configuration with coturn's client. [The test](tests/smoke.sh) covers public and private peers, two relayed clients, credentials in the format that the transport module gives and bad ones, and secret exposure. It is a failure-risk test of this configuration and carries no requirement IDs. [smoke-test.md](docs/smoke-test.md) says how it runs coturn and its client; read it before changing `smoke.sh`. The requirements of the transport module about TURN, such as that coturn accepts the credentials of the transport server ([8-2](../transport/docs/specs/8-turn.md)) and relays between two pages that reach each other only through it ([8-5](../transport/docs/specs/8-turn.md)), have browser tests of the transport module, whose runner starts coturn with `turnserver.conf` and `start.sh`, as [browser-tests.md](../../docs/browser-tests.md) says. Run them too when changing TURN configuration, startup or image: `pnpm test:browser platform/transport` from `games/`. [check-turn.yml](/.github/workflows/check-turn.yml) runs `smoke.sh` on every run of `games.yml` and in [ci.yml](/.github/workflows/ci.yml) when a change needs it; `ci.yml` runs the browser tests only when a package of `games/` changes, and `games.yml` runs them all before every deploy, as [checks.md](/.github/docs/checks.md) says.
