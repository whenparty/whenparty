# Deployment

[compose.yml](../compose.yml) defines the container; [turnserver.conf](../turnserver.conf) defines network restrictions and quotas. [start.sh](../start.sh) adds the shared secret and detects the public address behind NAT.

## Constraints

- Set the repository secret `TURN_SECRET` for both TURN and [signaling](../../signaling/AGENTS.md). The [deploy workflow](/.github/workflows/deploy-project.yml) writes it to the private `.env` of both [deployments](/docs/glossary.md#deployment), as [deploys.md](/.github/docs/deploys.md#deploy-projectyml) says. TURN exits without it; signaling then issues no credentials (`8-1` of [8-turn.md](../../transport/docs/specs/8-turn.md), [server.md](../../signaling/docs/server.md#http)).
- DNS for `turn.when.party` must point directly to the VPS without Cloudflare proxying. Open `3478/udp`, `3478/tcp` and `49152-49407/udp` in both firewalls. coturn has no TLS endpoint. Its container uses the host network: coturn relays each allocation on a port of its own from `49152-49407/udp` and needs the clients' real addresses, and publishing a range of ports through Docker is slow and hides those addresses.
- Keep the secret out of Git, logs and process arguments. The generated config belongs in private `/tmp` storage. Retain the container restrictions in Compose and its one added capability, `NET_BIND_SERVICE`: the image's `turnserver` binary carries it as a file capability, and the kernel refuses to run the binary when the container's bounding set lacks it. The capability allows nothing but binding ports below 1024, and coturn binds none.
- Deny private and special-use peer addresses. Keep the server's own public address allowed so two relayed clients can connect. No other UDP service may listen on that public address; inspect listeners with `sudo ss -ulpn` when provisioning.
- Do not add denied IPv6 ranges starting at `::`; coturn also matches IPv4 peers against them. Keep UDP relay allocations only (`8-5` of [8-turn.md](../../transport/docs/specs/8-turn.md)) and retain the resource quotas: 64,000 bytes a second for each allocation out of 8,000,000, so at most 125 allocations at once, and at most 32 for one username; [turn-credentials-limit.md](../../docs/decisions/turn-credentials-limit.md) explains why they, and no limit on credentials, bound its use. When none is free, a peer connection that needs TURN closes with `no relay` (`3-9` of [3-connection.md](../../transport/docs/specs/3-connection.md)).
