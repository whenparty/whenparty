# Pages of a participant

- `5-1` A browser keeps one record for each app ID in `localStorage`: the room code, the token, the room's waiting time and the data that the app adds. Creating or joining a room replaces the record of the app ID. When writing the record fails, the page goes on without writing it. When `localStorage` cannot be read, the page has no record.
- `5-2` A page acts for a participant only while it is the participant's controlling page in its browser: it alone has peer connections for the participant, and sends and gets its texts. At most one page of a browser is the controlling page of a participant. The other pages of the participant view (5-6). The rooms module tells the app "control gained" and "control lost" each time this changes for its page.
- `5-3` When a page creates, joins or returns to a room while another page of its browser controls the same participant, it asks that page to give control up and waits for it. That page stops sending and getting texts, lets its app write its data to the record, closes its peer connections, and only then gives control up and views. The asking page then gets control, lets its app read the record, returns ([2-6](2-join.md)), and only then connects to other pages.
- `5-4` A page waits for control without a time limit, and views while it waits, such as when the controlling page does not answer because the browser suspended its scripts. When the controlling page closes or the browser discards it, the page that asked first gets control. A page that gave control up waits for it again, after the pages that asked before it.
- `5-5` Each time a page tells the rooms server that it controls the owner's participant, the server raises the owner's term by 1 and tells the page the term and the room's roster: for each participant that got a token in the room, its public number and status, which is "online" when its controlling page has an open signaling connection, "offline" otherwise, and "left" when its token was cancelled. The owner's app is told the roster, and the page counts each participant that has not left as lost ([4-1](4-presence.md)) from then, without telling "lost".
- `5-6` A viewing page gets first the data that the app on the controlling page gives for it, then each item that this app publishes to viewing pages, in the order published. A viewing page sends nothing for the participant to other pages or to the rooms server, except that it can leave the room, which goes as when the controlling page leaves ([4-5 and 4-6](4-presence.md)).
