# Participants on the owner's page

- `6-1` When the rooms server asks the owner's page about a join ([12-2](12-server-answers.md)), the app is told a join request with the number that the participant would get and the join data of the request. The app answers by letting the participant in or by refusing, and a refusal may carry join data ([1-15](1-room.md)); a refusal with a value that is not join data goes without it. When the handler of join requests throws, or its promise rejects, the page refuses. The page sends only the first answer to a request, and only while the request is pending (6-2).
- `6-2` A join request is pending from when the app is told of it until the app refuses it, the server names its number (6-3) or it ends. When a pending request ends because the server ends it ([11-4](11-server-participants.md)) or the page's signaling connection closes, the app is told once that the request ended, with the number. An answer that let the participant in and reached the server before its connection closed stays in force ([10-5](10-server-room.md)): the number then comes in the roster (6-9).
- `6-3` The rooms server names a number to the owner's page with a peer ID when it lets the participant in or accepts its return ([11-5](11-server-participants.md), [11-6](11-server-participants.md)), before that peer ID can call the page ([1-11](../../../transport/docs/specs/1-signaling.md)). From then on, the page keeps an incoming peer connection ([3-3](../../../transport/docs/specs/3-connection.md)) for the number only from that peer ID, one at a time: a newer one from it closes the older one. The page closes the number's peer connections from other peer IDs, and when one of them was open for rooms, the app is told "lost". It closes an incoming peer connection from a peer ID that is not named for any number. What arrives later over a peer connection that the page closed changes nothing.
- `6-4` A number that the server named to the page and whose peer connection is not open for rooms is lost. Its loss starts when the number was first named, or, when its peer connection that was open for rooms closed, at the last time anything arrived over that connection, as the transport reports with its closing ([3-15](../../../transport/docs/specs/3-connection.md)). The start does not move when the number is named again, its peer ID changes, a new attempt starts or the owner's page starts anew ([5-2](5-owner-return.md)). Only a peer connection that opens for rooms ([1-8](1-room.md)) ends the loss.
- `6-5` The app is told these events about each number, each once for each cause, in the order of the causes:
  | Event | When |
  | --- | --- |
  | joined, with the visibility | the number's peer connection opens for rooms for the first time |
  | back, with the visibility | it opens for rooms again |
  | hidden or visible | the participant's page sends its visibility over a connection that is open for rooms |
  | lost | the number's connection that is open for rooms closes, or the page closes it as 6-3 says |
  | left | the number is removed (6-7) after the app was told "joined" |

  The app is told nothing about a number after "left", and nothing about a number that is removed before "joined".
- `6-6` The page sends texts ([7-1](7-texts.md)) and its confirmation ([1-8](1-room.md)) to a number only over its peer connection from the peer ID last named.
- `6-7` The page removes a number when the waiting time has passed since its loss started, when the participant's leave arrives over its peer connection, when the server tells the page that the participant left ([11-7](11-server-participants.md)), or when a roster leaves it out (6-9). The page then closes the number's peer connections. Unless it learned of the removal from the server, it tells the server the participant's leave over the owner connection: at once when the page has the owner connection, and otherwise with its next request to reconnect ([4-5](4-owner.md)) or to return ([5-1](5-owner-return.md)), or right after that request succeeds when the number was removed while it was under way.
- `6-8` The page never takes back a removed number. When the server names it again or a roster includes it, the page closes its peer connections and tells the server its leave again, as 6-7 says.
- `6-9` When the server answers a request to reconnect with the roster ([4-5](4-owner.md)), the page removes each number that it knows and the roster leaves out, without telling the server. A number of the roster that the page does not know is lost since the answer.
