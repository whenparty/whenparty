# Rooms

- `1-1` The code that uses the rooms module on a page is called the app below. The rooms module gives the app rooms over the transport module. It has a part on each page and a server part ([1-1](../../../transport/docs/specs/1-signaling.md)), called the rooms server. A page talks to the rooms server over a signaling connection ([1-1](../../../transport/docs/specs/1-signaling.md)) and to other pages over peer connections ([3-1](../../../transport/docs/specs/3-connection.md)).
- `1-2` An app ID has 1 to 64 characters, each a lowercase Latin letter, a digit, `.`, `-` or `/`. A room belongs to one app ID and has a code that no other open room of that app ID has. A code finds only a room of the same app ID.
- `1-3` A room code has 5 characters from `23456789BCDFGHJKMNPQRSTVWXYZ`. The rooms module turns text that a person typed into a room code: it removes every character that has the Unicode property White_Space and every `-` (U+002D), turns each letter from a to z into its capital, and says whether the result is a room code.
- `1-4` A room has one owner, the participant whose page created it, and other participants that the owner's page lets in ([6-1](6-presence.md)). In this specification "participant" means a participant other than the owner, unless a rule says that the owner is included. Each participant is connected only to the owner.
- `1-5` Each participant, the owner included, has a public number, called its number below, and a token. The owner's number is 1. Numbers and terms ([4-3](4-owner.md)) are whole numbers from 1 to 2,147,483,647. The rooms module tells an app numbers and never tokens: a token is known only to its participant's pages and the rooms server.
- `1-6` A room has a waiting time, which the app gives when it creates the room ([4-2](4-owner.md)): a whole number of seconds from 60 to 86,400, or none, which means 600 seconds.
- `1-7` The rooms module measures its time limits on a page by the clock of [1-7](../../../transport/docs/specs/1-signaling.md) of the transport. When the page's scripts resume after they were suspended or the device slept, the rooms module first acts on each of its time limits that passed, before it handles what arrived in the meantime.
- `1-8` When a peer connection between a participant's page and the owner's page opens ([3-14](../../../transport/docs/specs/3-connection.md)), the participant's page sends its visibility, "visible" or "hidden" as the browser reports it, before anything else. On the owner's page the connection is open for rooms when that first visibility arrives, and the page then sends a confirmation. On the participant's page it is open for rooms when the confirmation arrives. It stays open for rooms until it closes. The wait for the visibility and the confirmation has no time limit of its own, and the transport's checks do not end it ([4-8](../../../transport/docs/specs/4-delivery.md)): it ends only when the peer connection closes or a time limit of [2-9](2-join.md), [3-7](3-participant.md) or [6-7](6-presence.md) passes.
- `1-9` After it sent its first visibility over a peer connection to the owner's page, and while that connection is open, a participant's page sends its visibility over it each time the visibility changes.
- `1-10` The rooms module tells the app the path and round-trip time of each peer connection that is open for rooms: on a participant's page its connection to the owner's page, and on the owner's page each participant's. When the connection opens for rooms, the app is told the latest that the transport reported ([3-14](../../../transport/docs/specs/3-connection.md), [4-6](../../../transport/docs/specs/4-delivery.md)), and then each one that it reports.
- `1-11` When a handler that the app gave the rooms module throws, or returns a promise, the rooms module goes on as if the handler had returned, and ignores the promise and its rejection, except for a join request ([6-1](6-presence.md)).
- `1-12` A request of a page to the rooms server to create, join, return or reconnect gets no answer when the page has no answer 15 seconds after it sent it, or, after "asked" arrived for a join request ([2-3](2-join.md)), no final answer 65 seconds after "asked" arrived. The page then closes that signaling connection.
- `1-13` A signaling connection cannot open when it closes with `offline` before it is open ([1-4](../../../transport/docs/specs/1-signaling.md), [1-5](../../../transport/docs/specs/1-signaling.md)). One that the transport refuses as outdated ([1-2](../../../transport/docs/specs/1-signaling.md)) is not one that cannot open ([8-6](8-ending.md)).
- `1-14` A call of the app fails when the rooms module rejects it at once: nothing is sent and nothing else changes. Creating, joining or returning that fails with a reason ([8-4](8-ending.md)) is not a call that fails.
- `1-15` Join data is a JSON value of at most 1,024 bytes as compact JSON. A join request and a refusal of one carry it ([2-2](2-join.md), [6-1](6-presence.md)).
