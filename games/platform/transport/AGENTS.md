# Transport

`transport/` is the transport [module](/docs/glossary.md#module) of the [platform](../AGENTS.md). It gives pages signaling connections to the transport server, on which the server parts of other modules get channels, and peer connections to each other, directly or through the TURN server. The module spans this folder, which holds the package `@whenparty/transport` with its page part in `src/` and the transport server in `src/server/`, and [turn/](../turn/AGENTS.md), which holds the TURN server. The transport server runs in the [signaling deployment](../signaling/AGENTS.md), which hands WebSocket upgrade requests over to it and completes, with `ws`, those that the transport server accepts: the code in `src/server/` checks their path ([1-13](docs/specs/1-signaling.md)) and origin ([7-6](docs/specs/7-server.md)) itself, with an origin list of its own beside the one of the [p2p relay](../signaling/docs/server.md#code-and-origins).

- [docs/specs/](docs/specs/): its specification. Files 1 to 5 hold what the modules that use the transport get: signaling connections, server parts, peer connections, texts and who may call. Files 6 to 8 hold how the transport server handles calls, its limits, and TURN.
- [turn-credentials-limit.md](../docs/decisions/turn-credentials-limit.md): why the transport server gives TURN credentials without a limit. Read it before limiting the TURN credentials that a page or client gets.
- [websocket-library.md](../docs/decisions/websocket-library.md): why the transport server takes its sockets from the signaling deployment and has no WebSocket library of its own. Read it before adding a dependency to transport or changing the socket in `src/server/api.ts`.
- [layers.md](../docs/decisions/layers.md): why transport, rooms and netcode are modules of their own, why coturn is part of transport, and why the deployments that run the servers are not modules. Read it before moving code or rules between the modules.
