# Calls and signals

- `6-1` When a call reaches the transport server, the server rejects it with the first of these reasons that applies, and otherwise accepts it:
  - `failed`, when the caller's remaining time (6-4) is not a whole number of milliseconds from 1 up to the 15 seconds of [3-5](3-connection.md), when the caller's description is over the 16,384 bytes of 6-5, or when a live call record has the call's identifier;
  - `no peer`, when no open signaling connection has the called peer ID, it is the caller's own, or the list of the called connection lacks the caller's peer ID ([5-1](5-allow-list.md));
  - `busy`, when the called connection is the callee of 12 live call records, or of 2 with this caller, or the caller's connection is the caller of 64.

  The server tells the caller the reason at once. A rejected call creates no record, and the called page is not told of it.

- `6-2` When it accepts a call, the server creates a call record with the call's identifier, both peer IDs and the server's deadline, and at once passes the call with the caller's description to the called page. A record is live until the server forgets it (6-5, 6-6). The server never forgets a record to make room for another.
- `6-3` A signal is a description, or a batch of candidates, that a page sends for a peer connection. The server passes signals and one closing message only between the two pages of a live record, holds nothing back and passes them in the order they arrive. It drops the ones of no live record, and the ones from a page that is not of the record.
- `6-4` A call carries the caller's remaining time until its deadline ([3-5](3-connection.md)), rounded up to a whole millisecond. The server's deadline is the moment it gets the call plus that time. With the call, the server passes the called page its own remaining time, rounded up.
- `6-5` From each page of a record, the server passes one description, the caller's being the one in its call, and at most 32 candidates in batches, of at most 16,384 bytes in all. These bytes are the UTF-8 bytes of the description's text, with any candidates inside it, and of each candidate's text. Candidates inside a description do not count toward the 32. When a page sends a signal beyond these limits, the server does not pass it, tells both pages that the attempt closed with `failed`, and forgets the record.
- `6-6` The server forgets a record when it passes the first closing message of either page to the other, or when the record's deadline passes. When the signaling connection of either page closes, the server tells the other page `peer offline` and forgets the record. The server does not see a peer connection open, so the record of an open one lives until its deadline and counts toward the limits of 6-1 until then.
- `6-7` The page keeps its signals within the limits of 6-5. It sends its description first, without candidates, and then its candidates in batches, each once: at most 16 host, 8 server-reflexive and 8 relay candidates, and none that would take its signals over 16,384 bytes.
- `6-8` A candidate of the other side that arrives before that side's description is not lost: the page uses it once the description has arrived. The page drops a signal with an identifier that it does not know, or from another peer ID than the other side's.
