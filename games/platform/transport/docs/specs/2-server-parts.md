# Server parts

- `2-1` The transport server passes each module message that it reads from a signaling connection to the server part of its channel, with the peer ID of that connection, in the order of [1-11](1-signaling.md).
- `2-2` A server part can send a module message ([1-10](1-signaling.md)) to any open signaling connection by its peer ID. When no open signaling connection has that peer ID, or the connection has no channel of the server part's [module](/docs/glossary.md#module), the server drops the message without telling the server part. When a server part sends a value that [1-10](1-signaling.md) does not allow, sending fails and nothing is sent.
- `2-3` When a signaling connection that has a peer ID closes, for any reason, the server tells each server part with a channel on it once, with the peer ID, as soon as it decides to close the connection and after it passed the server part every message that it read from the connection. Messages from the connection that the server has not read are lost, and after the notice it passes nothing from the connection.
- `2-4` The server does not wait for a promise that a handler of a server part returns. When the handler throws or its promise rejects, the message or notice counts as delivered, and the transport goes on.
