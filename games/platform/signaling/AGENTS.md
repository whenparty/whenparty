# Signaling

`signaling/` is the [deployment](/docs/glossary.md#deployment) of the [platform](../AGENTS.md) at `signaling.when.party`, not a module. It runs the relay through which the [p2p module](../p2p/AGENTS.md) finds peers and negotiates WebRTC, and gives p2p its TURN credentials at `GET /turn-credentials`. It also runs the transport server of the [transport module](../transport/AGENTS.md), with the rooms server of the [rooms module](../rooms/AGENTS.md) in it. It hands WebSocket upgrade requests to the transport server, which decides itself which to accept by their path, `/platform` ([1-13](../transport/docs/specs/1-signaling.md)), and their origin ([7-6](../transport/docs/specs/7-server.md)). Signaling gives the requests at other paths to the relay. Each deploy restarts it and so ends every room of the rooms module ([10-1](../rooms/docs/specs/10-server-room.md)); [room-storage.md](../docs/decisions/room-storage.md) explains why.

[src/server.mjs](src/server.mjs) owns HTTP, the relay's WebSockets with their heartbeat and resource limits, and the `ws` server that completes the upgrades the transport server accepts, as [websocket-library.md](../docs/decisions/websocket-library.md) explains. [docs/relay.md](docs/relay.md) explains the relay's limits and heartbeat; read it before changing them. [src/origin.mjs](src/origin.mjs) defines the origins that the relay and `GET /turn-credentials` allow; the transport server keeps its own list, and the two stay apart while p2p is in use. Keep the relay's heartbeat and the transport server's checks every 15 seconds ([7-2](../transport/docs/specs/7-server.md)) below proxy idle timeouts, such as the 90 seconds of requirement `2-5` in the [proxy's specification](/infra/docs/specs/2-headers.md), and retain the separate signaling limits in [games.conf](/infra/nginx/conf.d/games.conf), which [games-conf.md](/infra/docs/games-conf.md) explains. Origin filtering restricts browser use; it does not authenticate clients.

`GET /health` is the container health check. `GET /turn-credentials` returns uncached credentials, which only p2p uses, to every request from an allowed origin, or, when TURN is disabled, 404 with the same CORS headers, so that p2p reads it and connects without TURN. [src/turn.mjs](src/turn.mjs) makes them in the format and with the lifetime of [8-2](../transport/docs/specs/8-turn.md), without a limit, as [turn-credentials-limit.md](../docs/decisions/turn-credentials-limit.md) explains. Follow the [TURN instructions](../turn/AGENTS.md) for shared configuration. Keep secrets on the server.

Signaling and P2P take `@trystero-p2p/ws-relay` from the catalog in [pnpm-workspace.yaml](../../pnpm-workspace.yaml), so both speak the same Trystero protocol. Change its version there and update `pnpm-lock.yaml` in the same commit.

## Verification

Run `pnpm --filter @whenparty/signaling test` from `games/`. [Tests](src/tests/) cover allowed origins, HTTP responses, the relay's WebSocket limits, heartbeat and credentials, and the hand-over of upgrades at `/platform` to the transport server and its rooms server. Dependency updates also require the full workspace tests and typecheck.

Start locally with `pnpm --filter @whenparty/signaling start`; P2P uses `ws://localhost:8080`. The [Dockerfile](Dockerfile) uses `games/` as its build context. [compose.yml](compose.yml) defines production settings; [deploys.md](/.github/docs/deploys.md#deploy-projectyml) says how it deploys, and [games-changes.md](/.github/docs/games-changes.md) which changes redeploy it, changes to the transport and rooms packages included.
