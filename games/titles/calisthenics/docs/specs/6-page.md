# Page

- `6-1` The start screen of both interfaces has a button Create a room, which starts a game ([2-3](../../../../platform/netcode/docs/specs/2-page.md)), and a form that enters a game by its room code. When the form is submitted with text that the netcode does not turn into a room code ([2-4](../../../../platform/netcode/docs/specs/2-page.md)), it says "That is not a room code. Codes have 5 characters, like K7MXQ.", and otherwise the page enters that game ([2-5](../../../../platform/netcode/docs/specs/2-page.md)). When a page opens at an address whose part after `#` the netcode turns into a room code, it enters that game. Once the page has the room code of its game, it replaces its address, without a new history entry, with one that ends in `#` and the code.
- `6-2` From when the page starts or enters a game until the button is pressed, both interfaces show the room in place of the start screen, with a button Leave the room on every screen, also while the page enters or waits for the host ([3-2](../../../../platform/netcode/docs/specs/3-entry.md)), and after starting or entering fails or the game ends ([2-1](../../../../platform/netcode/docs/specs/2-page.md)). Pressing it leaves the game ([2-11](../../../../platform/netcode/docs/specs/2-page.md)) unless it has failed or ended, which for the host ([2-3](../../../../platform/netcode/docs/specs/2-page.md)) closes the room for every page, and shows the start screen. It replaces the address, without a new history entry, with one that has no room code, and from then on the page has no room. After starting or entering fails or the game ends, the room shows no controls for actions.
- `6-3` When the part of the address after `#` changes to the code of another room than the page's, the page leaves its game, if it goes on, and enters that room. When it changes to the code of the page's room, to text that the netcode does not turn into a room code, or is removed, the page stays as it is.
- `6-4` The host's page lets in every participant of each join request that the netcode tells it of ([4-3](../../../../platform/netcode/docs/specs/4-seats.md)), as soon as it is told.
- `6-5` A seated player's action goes to the host at once while the page can act ([8-1](../../../../platform/netcode/docs/specs/8-actions.md)). The actions are a name ([3-1](3-match.md)), an appearance change ([4-1](4-presentation.md)), confirming a plan, and the host's start of training, start of the challenge, Next athlete and next challenge ([3-3](3-match.md), [3-5](3-match.md)); picking the actions of a plan before confirming it is none. When the netcode answers an action with "cannot act" ([8-2](../../../../platform/netcode/docs/specs/8-actions.md)), such as while an earlier action awaits its answer or the host is away ([3-6](../../../../platform/netcode/docs/specs/3-entry.md)), the page keeps it. An appearance change made while the last kept action is an appearance change merges into it, with the latest value of each part, and a name made while a name is kept replaces it in its place. Each time the netcode tells that the page can act, the page drops the kept actions made on another screen or challenge than the one its last snapshot shows, then sends the first kept action left; when the netcode answers that it is not an action or too large ([8-2](../../../../platform/netcode/docs/specs/8-actions.md)), the page drops it and sends the next. Kept actions live only in the page's memory: the page drops them all when it reloads, leaves its game (6-2, 6-3), or entering fails or the game ends ([2-1](../../../../platform/netcode/docs/specs/2-page.md), [2-7](../../../../platform/netcode/docs/specs/2-page.md)).
