# Architecture

[.dependency-cruiser.cjs](../.dependency-cruiser.cjs) checks the import rules below.

- [src/core/](../src/core/index.ts) is the game's mechanics: rules, championship state and what each screen shows. It has no browser, page, network or three.js code. Within the game it imports nothing outside `src/core/`, and from the [netcode module](../../../platform/netcode/AGENTS.md) and three.js it imports only types.
- `src/core/` holds every rule of the [specification](specs/) that decides state or numbers, including those that only the 3D interface shows, such as the podium steps of `4-4` in [4-presentation.md](specs/4-presentation.md) and the repetitions of `5-4` in [5-movements.md](specs/5-movements.md).
- `src/core/` also holds the state that players share, such as the choices in an athlete's profile.
- `title` in [src/core/championship.ts](../src/core/championship.ts) holds the app ID, waiting time, format version and rules that the game gives the netcode (`1-1` of the netcode's [1-rules.md](../../../platform/netcode/docs/specs/1-rules.md)), with "lobby" for the state before the championship. The netcode sends the championship state and actions between pages as JSON, so `Championship` and `Move` hold only plain objects, arrays, strings, finite numbers, booleans and `null`. `isHostSeat` takes the player in the first seat as the host, because the netcode seats the host there until it leaves the game (`4-7` of [4-seats.md](../../../platform/netcode/docs/specs/4-seats.md)). "over" always answers no, so players who enter during the championship watch, and "can start" answers no once a match has started (`3-2`, `3-3` and `3-7` of [3-match.md](specs/3-match.md)).
- Wording, default looks and anything else that only changes how the game looks belong to frontends, not to `src/core/`.
- [src/connection.ts](../src/connection.ts) connects a page to a game of the netcode: it starts and enters games, puts the room code in the address, leaves, lets in every join request, and keeps the actions that the page cannot send yet ([6-page.md](specs/6-page.md)). Within the game it imports only `src/core/`.
- Each folder in `src/frontends/` other than `shared/` is one interface from the specification: `text/` is loaded by `text.html`, `3d/` by `index.html`. Its `main.ts` connects to the room and passes the room state and the player's actions to the elements it shows. Within the game a frontend imports from `src/core/`, `src/connection.ts` and `src/frontends/shared/`, and nothing from another frontend.
- [src/frontends/shared/](../src/frontends/shared/) holds texts, page elements and assets, such as the favicon, that more than one frontend uses. Texts are functions of `src/core/` data. Elements build their own markup inside an element the frontend gives them. Within the game it imports `src/core/` and only types from `src/connection.ts`.
- [src/frontends/3d/assets/](../src/frontends/3d/assets/) holds the 3D assets. When you add or change one, update its attribution in [CREDITS.txt](../src/frontends/3d/assets/CREDITS.txt) there.
