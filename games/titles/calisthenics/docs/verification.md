# Verification

Run these from `games/`:

- `pnpm --filter @whenparty/calisthenics test` runs the tests in [src/tests/](../src/tests/) in Node, apart from those that end in [`.browser.test.ts`](/docs/conventions/tests.md), and, when they pass, checks the import rules of [architecture.md](architecture.md).
- `pnpm test:browser titles/calisthenics` runs the tests that end in `.browser.test.ts` in a browser, as [browser-tests.md](../../../docs/browser-tests.md) says.
- `pnpm --filter @whenparty/calisthenics typecheck` checks the types of `src/` and `vite.config.ts`.
- `pnpm --filter @whenparty/calisthenics build` builds both entries, `index.html` and `text.html`.

The requirement tests in Node check `src/core/`, the files `appearance.ts`, `presentation.ts`, `exercises.ts` and `athlete-model.ts` of `src/frontends/3d/`, the title's rules with the context that the netcode gives them where a requirement depends on seats and presence, and the page of [src/connection.ts](../src/connection.ts) with a fake netcode; the state tables `3-match.states.ts` and `6-page.states.ts` in [src/tests/](../src/tests/) hold the states of the championship and of the page. [src/tests/fixtures.ts](../src/tests/fixtures.ts) builds championships for the tests in Node. Each browser test leaves its rooms, as [browser-tests.md](../../../docs/browser-tests.md#test-pages) says, with the button Leave the room (`6-2` of [6-page.md](specs/6-page.md)). The browser tests check:

| File                                                                          | Kind               | What it checks                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [4-presentation.browser.test.ts](../src/tests/4-presentation.browser.test.ts) | requirement tests  | `4-5` of [4-presentation.md](specs/4-presentation.md) on the 3D page: that it says 3D is unavailable and links to the text interface for the same room when the browser has no WebGL and when `athlete.glb` fails to load, and that the athlete the page shows while it is in no room stands still while the browser asks for reduced motion and moves when it stops asking.                                                                            |
| [text.browser.test.ts](../src/tests/text.browser.test.ts)                     | failure-risk tests | On the text page: that, while the announcement (`3-3` of [3-match.md](specs/3-match.md)) covers it, Tab reaches only the controls of the announcement and Leave the room, that the link to the 3D interface can take focus again after the announcement, and that the caption NOW PERFORMING, the athlete line and the clock of the Now performing card each have a contrast of at least 4.5:1 against the card in the light and the dark color scheme. |
| [3d-style.browser.test.ts](../src/tests/3d-style.browser.test.ts)             | failure-risk tests | On the 3D page: that the toolbar over the scene is 12 px from the top of the scene in a window 800 px wide and 18 px in one 1280 px wide; and, while the page shows the lobby in a window 375 × 812 px, that no visible text is smaller than 12 px and, under touch emulation, where `(pointer: coarse)` matches, that no visible button, select, input or link is less than 44 px wide or high.                                                        |

Check by hand in a browser what the browser tests leave out: the scenes and movements that [4-presentation.md](specs/4-presentation.md) and [5-movements.md](specs/5-movements.md) describe, including the still poses of the announcement, results and podium under reduced motion, the transitions between animations, the layout of 12 athletes (`3-1` of [3-match.md](specs/3-match.md)) and switching between the interfaces (`4-2` of [4-presentation.md](specs/4-presentation.md)). On a phone, where `(pointer: coarse)` matches, check that the text and controls of the 3D page, the top bar and the footer included, stay readable and usable without clipping, overlap or sideways scrolling of the page. With the browser's default font size at 16 px, resize the window until the browser's developer tools show the content width of `.visual-stage` just under and just over 35rem (560 px), once with the scene above the panel and once beside it, with Replay shown: just over, the toolbar over the scene stays on one line; just under, it takes its narrow layout and stays inside the scene without overlap. To run the game locally, start signaling as [workspace.md](../../../docs/workspace.md#running-a-title-locally) says, then run `pnpm --filter @whenparty/calisthenics dev`.
