# Documentation

- Use the minimum text needed in documents and responses. Describe only current behaviour. Replace or delete superseded text without adding change histories or before-and-after narratives. Keep history in Git.
- Describe each rule in one place and link to it elsewhere.
- Add documents only when existing references cannot supply the context needed for the task. Describe behaviour and contracts without retelling code.
- Include boundary cases in tests. Documentation should state the rule and link to the tests instead of duplicating every assertion.

For prose-only changes, check references and consistency. Remove duplicate or contradictory descriptions.
