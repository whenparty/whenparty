# Serving

These rules apply to the files that this repository serves to browsers from its own images and configs, on the sites and in the games, and to the builds and configs that produce and serve them. The [code rules](/docs/conventions/code.md) apply to these files too.

- The files work in the two latest stable major versions of Chrome, Edge, Firefox and Safari on computers, of Safari on iOS and of Chrome and Firefox on Android. Each major version counts at its latest stable release. Whether one of these versions supports a web platform feature, such as a CSS property, a script API, an HTTP header or a media format, is read from the data of [caniuse.com](https://caniuse.com/) or [MDN browser-compat-data](https://github.com/mdn/browser-compat-data), not from a run in a browser. When the data lists only the latest version of a browser, as caniuse.com does for Chrome and Firefox on Android, that version stands for both. The files and the configs that serve them use a feature only when the data shows full support of the form they use, without a flag, in all these versions, or when visitors on the versions that lack it or support it in part lose only what the feature adds. The files use no polyfills.
- When a file that a page loads, such as a style, script, image or font, changes, no HTTP cache on the way, such as Cloudflare's or the browser's, gives the page the old version. So either the page asks for the file under a URL that changes with its content, through a hash of the content in the file's name or in a `?v=` query, or the server sends the file with `Cache-Control: no-cache` or `no-store`.
