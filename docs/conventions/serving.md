# Serving

These rules apply to the files that this repository serves to browsers from its own images and configs, on the sites and in the games, and to the builds and configs that produce and serve them. The [code rules](/docs/conventions/code.md) apply to these files too.

- The files work in the two latest stable major versions of Chrome, Edge, Firefox and Safari on computers, of Safari on iOS and of Chrome and Firefox on Android.
- The files and the configs that serve them use a web platform feature, such as a CSS property, a script API, an HTTP header or a media format, only when all these versions support the form they use, or when, in the versions without that support, the files lose only what the feature adds and nothing that a [specification](/docs/conventions/specs.md) of their code requires or that visitors need to use them. Support in a major version is the support in its latest stable release, such as the latest stable 26.x for Safari 26. When that release is installed where you work or you can reach it, a test there of the form the files use, with default settings, shows its support; otherwise its support is read from the data of [caniuse.com](https://caniuse.com/) or [MDN browser-compat-data](https://github.com/mdn/browser-compat-data): it supports a form when either shows that form supported in full and without a flag. A test in Playwright's Chromium counts for Chrome and Edge, apart from video and audio formats, and a test in its WebKit counts for Safari, apart from how styles and animations look and move. When caniuse.com lists only the latest version of a browser on Android, that version stands for both major versions.
- The files use a polyfill only when a requirement of a specification of their code cannot be met in these versions without one. Code that reaches the same result through another feature, such as `setTimeout` where `requestIdleCallback` is missing, is not a polyfill.
- When a file that a page loads, such as a style, script, image or font, changes, no HTTP cache on the way, such as Cloudflare's or the browser's, gives the page the old version. So either the page asks for the file under a URL that changes with its content, through a hash of the content in the file's name or in a `?v=` query, or the server sends the file with `Cache-Control: no-cache` or `no-store`.
