# Code

Keep comments to a minimum. Make intent clear through names, types and structure. Rewrite unclear code before explaining it. Put rules that code cannot express in the module's documentation, as described in [specification rules](specs.md). Remove comments that repeat code or documentation.

Put a helper, style or asset in the folder of the only code that uses it. When code in another folder needs it too, move it to the closest folder that both are allowed to import from.
