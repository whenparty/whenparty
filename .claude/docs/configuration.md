# Configuration

These notes say how to change the files in `.claude/`, which [.claude/AGENTS.md](/.claude/AGENTS.md) maps.

- Git ignores everything in `.claude/` except `AGENTS.md`, `settings.json`, `docs/`, `hooks/`, `agents/` and `skills/`, as [.gitignore](/.gitignore) sets. A new file that everyone needs gets an exception there. Other files, such as `settings.local.json`, stay on one machine.
- The `description` of a skill or subagent decides when Claude Code uses it on its own. [workflow.md](/docs/conventions/workflow.md), [workflow-specs.md](/docs/conventions/workflow-specs.md) and [workflow-checks.md](/docs/conventions/workflow-checks.md) name a skill or subagent where they call for it, so its description need not say when they do.
- The [`docs-reviewer`](/.claude/agents/docs-reviewer.md), [`behaviour-reviewer`](/.claude/agents/behaviour-reviewer.md), [`findings-verifier`](/.claude/agents/findings-verifier.md), [`last-reader`](/.claude/agents/last-reader.md) and [`spec-test-verifier`](/.claude/agents/spec-test-verifier.md) subagents have no Edit or Write tool, so that they only report. They keep Bash for commands that read, such as `git grep`, so only their instructions keep them from writing files through Bash. `behaviour-reviewer` also has WebSearch and WebFetch, to check the standards of the platforms a [specification](/docs/conventions/specs.md) relies on.
- The `model` field of `last-reader` sets the Sonnet model: the [last reading](/docs/conventions/workflow-checks.md#last-reading) comes after the reviews and is meant to be quick. The other subagents have no `model` field.
- The [`codex` skill](/.claude/skills/codex/SKILL.md) lists `codex exec` and `codex login status` in `allowed-tools`, so that Claude Code runs them without asking while the skill is in use. Only the skill's text keeps `codex exec` to the options it gives, and no hook or confirmation sees the commands that Codex runs.
- [settings.json](/.claude/settings.json) registers the hooks. It also asks for confirmation before editing any `package.json`. An `Edit` rule covers every built-in tool that writes files, but not Bash, so a command such as `sed -i` changes `package.json` without asking.
- It also asks before `pnpm add`, `pnpm install` and `pnpm i`, with or without options before the command. These confirmations, and the one for `package.json`, show the user a change of the dependencies of a `package.json` before it is made. They also ask for changes that add, remove or update no dependency, such as an edit of the scripts, `pnpm install` without a package name, or another `pnpm` command that contains `i` between spaces. They do not cover `npm`, `yarn` or `pnpm pkg set`.
- It lets Claude Code run `pnpm deps:cached`, the script of [games/package.json](/games/package.json) and of the root [package.json](/package.json) that installs the packages of its folder from its lockfile and only from pnpm's store on the machine, without asking. The script runs `pnpm install --frozen-lockfile --offline`: pnpm downloads no package, installs no version that the lockfile does not name, and fails when the store lacks a package. pnpm itself is downloaded first when the pnpm that runs is not the version that `packageManager` names, as [pnpm-in-images.md](/games/docs/decisions/pnpm-in-images.md) says. The confirmation of `pnpm install` above would ask for that command itself, and a confirmation wins over a permission, so the permission names the script. `pnpm install --frozen-lockfile`, which downloads a missing package, still asks.
- It denies `npx`, `npm x`, and, with or without options before the command, `npm exec` and `pnpm dlx`, so that such a command fails at once, in every permission mode, instead of waiting for a confirmation. `npx`, `npm x` and `npm exec` run a command from an npm package and download the package when the folder has not installed it, and `pnpm dlx` always runs a package that it downloads or has cached recently. Agents run the tools of the repository through its scripts and `pnpm exec`, such as `pnpm exec tsc`. The denial refuses one of them anywhere in a command, such as after `&&` or `||`, inside `$(…)` or after a variable assignment, but it matches the command text only, so a script, `sh -c`, `env` or a path such as `/usr/bin/npx` gets past it. `npm x` after options, such as `npm --yes x pkg`, is not denied. A denial wins over a permission and a confirmation in any settings file, so nobody can allow such a command for one run; a person who needs one runs it outside Claude Code. `pnpx`, the short form of `pnpm dlx`, stays out of the denial, since a denial of it would also refuse `pnpx modern-web-guidance@latest` below. [package-runners.md](/docs/decisions/package-runners.md) explains why.
- It names Google's marketplace `googlechrome`, turns on its auto-update, and enables its plugin `modern-web-guidance` in this repository. The description of the plugin's skill `modern-web-guidance` asks the agent to search and read Chrome's Modern Web Guidance through Google's CLI at the start of every task on HTML, CSS or client-side JavaScript other than those it leaves out, such as tests and renames, and its steps have the agent end its answer with a `### Modern Web Guidance` section; its skill `chrome-extensions` is for Chrome extensions. The setting does not download the plugin, so each person sets it up as [modern-web-guidance-setup.md](/.claude/docs/modern-web-guidance-setup.md) says.
- It lets Claude Code run, without asking and with any arguments, `pnpx modern-web-guidance@latest search` and `pnpx modern-web-guidance@latest retrieve`. The skill writes its commands with `npx -y` and says to prefer `pnpx` when pnpm, which the games need, is installed, and to retry with `npx --offline` when a command hangs offline; the denial above refuses these commands as the skill writes them, so the agent runs the CLI through `pnpx`. Each call runs the version that npm gives as the latest, or one that pnpm has cached from it recently, and no confirmation sees what that version does. The rules leave out the package's other commands, such as `list`, which the skill runs when a second search finds no fitting guide, or once for a broad audit of the interface, and `install`.
- A `SessionStart` hook written inline in settings.json writes `export DISABLE_TELEMETRY=1` to the file that `CLAUDE_ENV_FILE` names, which Claude Code runs before each Bash command of the session, so the CLI sends Google no queries and no guide IDs. Claude Code itself does not take the variable from this file, but a `claude` that a Bash command starts, such as the [evaluation](/.claude/hooks/docs/evaluation.md)'s `claude -p`, inherits it and turns off its own telemetry and feature flags.
- In auto mode, the classifier of Claude Code may decide these commands in place of the rules, and it can refuse them unless a person's own settings make an exception, as [modern-web-guidance-setup.md](/.claude/docs/modern-web-guidance-setup.md) says.
- A change to `settings.json`, its hook entries included, takes effect in sessions that are already running, apart from `SessionStart` hooks and plugins. A changed `SessionStart` hook runs when a session starts, resumes, is cleared or compacts, and a change to the plugins takes effect when a session starts or after `/reload-plugins`. A change to a hook script takes effect at its next run. In a session that the desktop app starts in a worktree, Claude Code reads settings.json and runs hooks from the main checkout, so a change takes effect there once the main checkout has it. So a broken hook can deny edits in the session that changed it. A new or renamed file in `agents/` or `skills/` is loaded when a session starts.
