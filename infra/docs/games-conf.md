# Working on games.conf

`games.conf` holds two servers: one for the games and one for `signaling.when.party`. [nginx-configs.md](nginx-configs.md) says how it combines with the shared settings, and [game-hosts.md](/docs/decisions/game-hosts.md) explains why the games share one host and have a config of their own.

- The server for the games names `games.when.party`, where every title has a path of its own, and the former hosts of titles, which redirect to those paths, as [hosting.md](/games/titles/docs/hosting.md) says. The server for `signaling.when.party` names the signaling server. [check-game-hosts.yml](/.github/workflows/check-game-hosts.yml) checks that the `server_name` entries of `games.conf`, across both servers, are exactly the `Host` labels of the deployments in `games/`, as [checks.md](/.github/docs/checks.md#the-checks) says. A host of a deployment in `games/` that is missing there falls to the wildcard server of `temp-sites.conf`, whose Content-Security-Policy blocks the signaling server.
- The server for the games redirects a path of one segment of lowercase letters, digits and hyphens without a trailing slash, such as `/tictactoe`, to the same path with the slash, because the Traefik router of each title matches only the path with it.
- The server for the games has a 404 page of its own in place of the shared one in [nginx-configs.md](nginx-configs.md). It turns every 404 that the index page or a title sends, and the 418 that Traefik's router `unknown-host` sends while the index page is down, into `nginx/conf.d/errors/games-404.html`, and keeps the status. `infra.yml` copies that file with the rest of the folder. The page copies the colours and fonts of the index page's [styles.css](/games/index/src/styles.css), so a change to them there needs the same change in `errors/games-404.html`. A title that needs its own 404 body needs a location for its path with `proxy_intercept_errors off`. The server for `signaling.when.party` passes its responses on unchanged, so it answers 418 while the signaling server is down.
- The Content-Security-Policy of the server for the games lets the games reach the signaling server, over WebSocket and for their TURN credentials. A change to the policy of the temporary sites does not need the same change here. Both policies allow the Cloudflare Web Analytics script that Cloudflare adds to every page. The script reports to `/cdn-cgi/rum` on the page's own host, which `'self'` covers.
- The signaling server has its own limits per client address, in zones of its own. Every player holds one WebSocket there, and the players of one party often share an address, such as one Wi-Fi or a mobile carrier's NAT, so the 15 connections that the other sites allow would shut the 16th player out. Its own zones also keep those sockets from using up the 15 connections that the game pages get. The signaling server limits what each socket does, keeps its heartbeat below `proxy_read_timeout`, and relies on these limits, as the [signaling documentation](/games/platform/signaling/AGENTS.md) says.
- The Content-Security-Policy of the server for the games and the Permissions-Policy of `default.conf` are copied to `games/platform/p2p/src/dev-headers.ts` for local game development, with the local signaling server added, as the [p2p documentation](/games/platform/p2p/AGENTS.md) says.
