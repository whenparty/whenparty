# Working on games.conf

`games.conf` holds two servers: one for the games and one for `signaling.when.party`. [nginx-configs.md](nginx-configs.md) says how it combines with the shared settings, and [game-hosts.md](/docs/decisions/game-hosts.md) explains why the games share one host and have a config of their own, and [games-routing.md](/docs/decisions/games-routing.md) why nginx reaches their containers itself.

- The server for the games names only `games.when.party`, where every title has a path of its own, as [hosting.md](/games/titles/docs/hosting.md) says. The former hosts of titles fall to the wildcard server of `temp-sites.conf`, as [former-game-hosts.md](/docs/decisions/former-game-hosts.md) decides.
- [4-games.md](specs/4-games.md) says where each path goes. The server reaches a title at the container `games-<name>` on port 80, the index page at the container `index` through the upstream `games_index`, and the signaling server at the container `signaling` on port 8080 through the upstream `games_signaling`. [sites.md](sites.md) says how nginx finds these containers. [check-game-names.yml](/.github/workflows/check-game-names.yml) checks that the titles' containers and those that the upstreams name keep their names and the network `wp_games`, and that no other container takes them, as [checks.md](/.github/docs/checks.md#the-checks) says.
- It removes `/<name>` with `rewrite ... break` before `proxy_pass`, because nginx sends a path that a variable in `proxy_pass` builds without encoding it again, so a `%20` or `%3F` in it would reach the title decoded. After `rewrite`, nginx encodes the path again, which is what requirement `4-1` of the [specification](specs/4-games.md) describes.
- The redirect of `4-2` exists because the location of the titles matches only a path with the slash after the segment.
- The server for the games has a 404 page of its own, `nginx/conf.d/errors/games-404.html`, in place of the shared one in [nginx-configs.md](nginx-configs.md), and shows it for 404, 502 and 504, as `4-4` says. nginx answers 502 when no container has the name of a path's title, so a path that names no title and a title whose container is down look the same. The page has `Cache-Control: no-store`, so Cloudflare does not keep a 404 from the seconds a title is redeployed. `infra.yml` copies that file with the rest of the folder. The page copies the colours and fonts of the index page's [styles.css](/games/index/src/styles.css), so a change to them there needs the same change in `errors/games-404.html`. A title that needs its own 404 body needs a location for its path with `proxy_intercept_errors off`.
- The Content-Security-Policy of the server for the games lets the games reach the signaling server, over WebSocket and for their TURN credentials. A change to the policy of the temporary sites does not need the same change here. Both policies allow the Cloudflare Web Analytics script that Cloudflare adds to every page. The script reports to `/cdn-cgi/rum` on the page's own host, which `'self'` covers.
- The signaling server has its own limits per client address, in zones of its own, as `2-4` of [2-headers.md](specs/2-headers.md) says. Every player holds one WebSocket there, and the players of one party often share an address, such as one Wi-Fi or a mobile carrier's NAT, so the 15 requests in progress that the other sites allow would shut the 16th player out. Its own zones also keep those sockets from using up the 15 that the game pages get. The signaling server limits what each socket does, keeps its heartbeat below the 90 seconds of `2-5`, and relies on these limits, as the [signaling documentation](/games/platform/signaling/AGENTS.md) says.
- The Content-Security-Policy of the server for the games and the Permissions-Policy of `default.conf` are copied to `games/platform/p2p/src/dev-headers.ts` for local game development, with the local signaling server added, as the [p2p documentation](/games/platform/p2p/AGENTS.md) says.
